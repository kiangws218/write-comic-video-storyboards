# Gen2.7 表演保真修订与第15话前八图评估

## 结论

本次修订保留了 Gen2.7 的按需加载结构，并补回规则压缩时丢失的局部表演保真门槛。文本层质量验收通过；视频运动效果仍需在同一模型、参考图、画幅、时长和随机策略下实跑 A/B，不能仅凭脚本断言等同。

用户指出的 `ch15_p07_c001` 退化已修正。新稿不再把“后撤、缩肩、摇头、视线折返”压成关键词摘要，而是明确自足起始姿态、两次拒绝的不同动作节点、眼睑/泪珠/嘴型变化、肩线与发袖延迟、镜头落幅及前后两声的声音差异。源图复核同时发现旧 Gen2.6 的“视线看向晶石/矮人/出口”与紧闭双眼冲突，因此没有机械恢复该细节，也移除了无证据的出口方向和指节避让。

## 规则与 Token

本测试因包含手部、晶石和接触关系，实际加载 `SKILL.md + core-authoring.md + dialogue-performance.md + cinematic-rendering.md + source-risk.md`。

| 加载规则字符 | 48,246 | 25,199 | -47.8% |
| 规则 Token 代理 | 17,421 | 7,377 | -57.7% |

相对上一轮 Gen2.7，新增的表演保真规则约增加 562 个规则 Token 代理，但仍比 Gen2.6 少约 10,044；输出没有被压缩，符合“只压规则、不压分镜正文”的目标。

Token 代理算法：中日韩字符按 1 计；连续 ASCII 按约 4 字符/Token；其余标点按约 2 字符/Token。它用于同仓版本比较，不等于 API 账单中的精确 tokenizer 结果。

## 规则与验证器修订

1. 新增“表演保真底线”：规则可压缩措辞，不得把开场、语义节点、承载部位、延迟响应和落点压成动作摘要。
2. 对 4–6 秒强情绪对白，按源图条件检查：动作先后/重叠、局部面部变化、身体或发衣延迟、具体表演落点。
3. 摄影机发生运动时，要求说明跟随对象和具体落幅。
4. 重复话语要求声音设计区分前后节拍；仅写“与动作同步”不算区分。
5. 验证器只从 `可见动作` 统计表演信号，避免环境、镜头字段中的关键词把低密度动作误判为合格。
6. 手部极近景按可见部位评估，不强迫补造面部或全身动作。

## 验证结果

- Skill 结构：`quick_validate.py` 通过。
- 验证器：34 项单元测试全部通过。
- 完整分镜严格验证：0 错误，13 条人工复核警告。
- 当前稿没有“表演保真槽缺失”“移动镜头无落幅”或“重复对白无声音节拍区分”警告。
- 13 条保留警告来自多说话人、长对白/长镜头、同图不同覆盖等人工判断点；台账已有对应 coverage/long-take 依据。

## 当前判断

Gen2.7 现在可以进入视频 A/B，而不是直接宣布最终质量等同。文本层面，规则 Token 仍显著低于 Gen2.6，输出密度更高，用户指出的典型表演退化已经修复并变成可回归检测的规则；视频层的自然度、稳定性与模型服从度仍需实跑验证。
