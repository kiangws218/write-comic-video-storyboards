# 可维护人物主档与未识别角色

项目已有姓名／设计主档时直接扩充该文件，不另起竞争入口。主档放在项目仓库内、跨话共享。当前迷宫干项目为 `comic-workspace/character-references/角色映射.md`，随项目维护，不把该漫画的人物当成适用于所有项目的 skill 内置事实。

每个条目维护：稳定ID、统一称呼、别称及身份状态；可辨设计和参考图；已确认的性格／表演基调及来源；配色方案及来源；变更日期、发生处和更名记录。人物参考图上的展示表情不是性格。长期性格、关系、临场情绪与本场任务分开；没有长期资料可以按本场情境导演，不编造恒定性格或要求先获批准。春子、青、董白按用户确认资料分别选择表演，而非同一套手势改幅度。

新话先读取出场条目，第三轮前核对更新；台账 character_registry 仅摘录本话用到的主档快照，character_registry_source 记路径、版本与读取日期，可加文件SHA-256。主档变更后评估受影响的本话演出并更新快照、重新审查；不得悄悄改变已冻结原文。工具绑定快照指纹，不声称自动监控外部主档。

未识别新角色在主档分配未占用稳定ID（如U001）和唯一中性代称，按外形结构与发生处辨别，不能所有“黑发女子”合成一人。同一人全话、跨话沿用一个名称；人物标签统一不改原句内部称呼。身份揭晓保留ID与旧称索引，之后按新记录使用，不无审核地改历史对白和交付。

同时为该角色确定稳定上色方案：优先已有彩色参考／用户要求，否则按漫画形制进行一致的生产设计。写全适用的发色、肤色、眼色、衣物、配件／材质与区分色，保留版型、纹样和显著特征，不凭黑白网点强认实际颜色，不称临时配色为官方资料。缺直接配色证据是warning，不阻止设计。

未识别条目在台账使用 id、canonical_name、aliases、identity_status:"unidentified"、performance_profile、color_prompt、color_basis。color_prompt 是可直接执行的上色提示词；color_basis 只在台账解释来源和设计选择。开篇集中显示“稳定ID｜统一代称：上色提示词”，放在所有片段之前，六字段使用同一称呼与色彩。新角参考图随后补齐时只更新来源与确认状态，不无故改变已用配色。

上色提示词不加入动作、机位、身份猜测、隐藏设定或每镜变化的照明色；灯光对固有色的影响另在镜内处理。没有未识别角色时不强加空白小节。规则实现格式见 [ledger-v282.md](ledger-v282.md)，颜色优先级与硬约束由 [core-authoring.md](core-authoring.md) 维护。
