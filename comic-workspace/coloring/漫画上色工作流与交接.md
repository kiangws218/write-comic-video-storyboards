# 漫画上色工作流与交接

更新：2026-11-16。适用范围：黑白漫画单格上色、角色一致性修订、按原条漫拼接交付。

本文件中的路径均以仓库根目录为基准，不依赖某台电脑的盘符。工作区入口：[comic-workspace/coloring/](./README.md)。

## 一、用户已确认的默认要求

1. **今后图片只交付PNG。** 单格、条漫和图片预览均使用PNG，不再额外生成JPG、PDF或其他图片格式。必要的交接说明、提示词和台账可以保留为Markdown、TXT或JSON。
2. **审阅用缩图，生成和排版用原图。** 默认将黑白单格预览长边限制在720像素；总览或画面较简单时可用576像素（0.8×720）。保持宽高比，不拉伸。这里的“720p/576p”是审阅分辨率约定，不把所有画面硬裁成16:9。
3. **条漫保持原尺寸。** 最终每张条漫的宽高、页序、分格、对白位置和留白以原条漫为准。缩略图不充当生成源图、排版源图或交付图。
4. **先确认环境再上色。** 根据整话梳理白天/夜晚、野外/室内、天气及转场；先让用户确认，不能从一张灰底特写推断整话环境。
5. **尽量少用灰色背景。** 原有纯色、灰色渐变背景可按情绪改成蓝紫、淡粉、淡青等，也可补成符合场景的实景。已有场景应保持空间、时间和光线连续。对白白底、页间白色留白及有明确作用的黑色气氛区照常保留。
6. **只上色及做指定修订。** 保持原作人物、表情、动作、构图、台词、拟声字及阅读顺序。人设图提供身份与配色，不把人设展示姿势、表情或其他服装带入漫画。
7. **源素材另存保护。** 黑白截图、原条漫、人设图不覆盖。新上色、修订、排版结果进入独立输出目录。
8. **工具拦截的处理已有授权。** 本轮用户选择“保留原画黑白，并在交付时标明”；不要擅自增加遮盖、换装或改台词，也不要反复尝试同一被拦截内容。若用户另作指示，再按新指示处理。

## 三、低消耗审阅方式

- 首轮读取文件清单、编号及尺寸即可，不要直接把全部原尺寸漫画和全部人设图送入上下文。
- 用576像素长边的单格缩图组成带文件名的总览，先判断人物、场景、顺序、缺格、超长图和切分风险。
- 写具体上色提示时，按需查看720像素长边的单格预览；文字、眼睛、耳形或手部看不清时，只放大对应局部。
- 超长条漫按阅读顺序切成审阅小段；不要为看一处细节反复加载整张长条漫。
- 已确认的角色配色和环境写入台账，后续复用；只读取当前格涉及的人设。
- 实际Image编辑引用原尺寸目标图及必要参考图。审阅缩图只是理解来源，不能替代原始输入。
- 第一版后局部修改继续用当前彩稿做编辑目标，明确只改哪些区域，减少全格重绘及重复说明。

## 四、确认角色与环境

### 角色核对

先读共享角色映射，再以发型、耳形、服装结构等组合辨认；最后核对实际彩色参考。不能只凭黑白发色深浅或“长发女性”套身份。

| 项目称呼 | 本轮需特别保持的配色或特征 |
|---|---|
| 青 | 银白长发、尖耳、红眼、蓝色上衣、白领/白领带/白裙；按当格服装状态着色 |
| 春子 | 棕发、深色眼部、半垂眼、低情绪外显、深色宽松连帽衣；不要改成大圆闪亮虹膜 |
| 善律 | 深棕长发、白衬衫、黑领带及黑色高腰裙；与春子区分 |
| 嫍巴士 | 紫发双发髻、红色虹膜；夸张表情和小虹膜也要保持红色，眼白保持白色 |
| 慧珍 | 金发、白兔耳、红眼、粉色内搭、棕色毛领外套；与青区分 |
| 董白 | 黑色双长马尾、浅色脸侧发束、蓝眼、黑色无袖高领服装 |
| 鬼头武士 | **使用`turnarounds/鬼头武士.png`原版，不用C版。** 棕褐头罩/手套、黑外衣、米色内衣；夜景冷光不应把底色变成蓝色 |

完整参考路径统一以前述`comic-workspace/character-references/`为前缀。用户最新明确指定的角色版本优先；不要因为文件名带“定稿”就替换用户选择。

每格台账至少记录：原文件名、对应角色/局部身份、实际采用的参考文件、环境、待核对处。倒置、拖行、背影、局部特写要从相邻格和原条漫确认。

### 环境确认

先列出明确转场和持续场景，向用户提出一次集中确认。用户确认后复用，遇到新的含混转场再问。本次第44话确认：前段野外白天；第28_001的大门及之后现实场景为夜晚；合照按照片本身的配色，不能整张套成蓝色夜景。

## 五、Image上色与局部修订

默认使用内置Image工具，一张目标资产对应一次编辑任务；独立任务可适度并行。不要因为批量或存盘需求擅自换成API/CLI、其他模型或规则填色。

引用图片时明确每张职责：目标漫画、角色配色参考、必要的上下文参考。参考只选当格相关角色，尤其不要把青的银发套到紫发角色，或把日常服装的白领带入原本没有衣领的镜头。

可复用提示词骨架：

```text
编辑目标：图1原漫画/当前彩稿。
参考职责：图2仅用于某角色配色/身份，不采用展示姿势、表情和无关衣装。
本格角色：逐一标明位置、身份、发色、眼睛和实际可见服装。
环境：已确认的时间、地点、光线；背景色与情绪。
改动范围：只上色，或列出本次局部修订。
必须保留：原线稿、表情、眼型、姿态、手部接触、人物大小位置、构图、分格、所有文字及白色气泡。
限制：不补新人物/物件/衣领/领带，不扩画，不加边框，不改变画幅。
交付：完整PNG。
```

修订时优先把“只改虹膜颜色”“只减淡脸部紫色阴影”等写清楚。小圆虹膜应填为可见红色，保留黑瞳孔和白眼白；眼型与配色是两件事，春子不能仅改眼睛颜色而保留错误的圆形高光眼型。

生成后立即保存PNG到本话输出区，记录提示词、目标及参考文件。逐张检查后再进入正式`逐格/`，不以“调用成功”代替验收。

## 六、按原尺寸还原条漫

1. 以原条漫为底，建立单格到原条漫的页号、坐标及尺寸对应表。原条漫中有而截图缺少的画面、标题、旁白要先补齐来源。
2. 漏分割的长图按完整画面和对白拆开；优先在留白/黑色间隔处切，不截断气泡、人物或连续动作；保留原图与切分坐标。
3. 检查Image结果与源格画幅。工具可能给超宽小格增加白边；先去掉新增边框，再按原格尺寸回贴，避免把眼睛、字和人物压扁。
4. 回贴到原条漫的原位置，保留原尺寸和阅读留白。对白必要时从原稿的明确文字/气泡区域回贴；保护范围不要覆盖角色眼睛、皮肤或彩色细节。
5. 夜景的黑色转场区和跨格气泡需要检查：生成图新添的白边、白底不能覆盖原来的黑色间隔。
6. 保留原条漫中未进入单格的标题、对白和结尾字样。拼接完成逐页核对，不能只把所有单格首尾紧贴。
7. 最终仅导出PNG，每张宽高与原条漫一致。更新部分单格时，只重新导出受影响的条漫页，并刷新对应预览与记录。

## 七、交付前检查与修订维护

- 文件：源格全部有处理状态；条漫页数、页序、宽高一致；没有漏格、重格、截字、接缝白边。
- 身份：角色、发色、眼睛、服装及参考版本正确；拖行/倒置人物仍须辨认身份。
- 表演：不改变原表情、眼型、动作、接触方式；春子保持人设中的半垂眼。
- 颜色：红眼在小虹膜和上下多个子格均可见；皮肤不过度偏紫，背景情绪色不应染成整张脸的底色。
- 环境：白天/夜晚分界正确，冰冻地面不能擅自画成海面，照片内部与现实照明分开处理。
- 文字：台词、旁白、拟声字及标题保持原文；原白色气泡和原黑色转场没有被误改。
- 格式：单格和条漫均为PNG；保留黑白的例外列明文件名与原因。

用户提出修订后：先备份受影响的单格和条漫，修改指定范围，核对实际拼接后的成品，再同步更新当前`逐格/`、`条漫成品/`、提示词、参考版本和修订说明。预览应来自最终拼接结果，避免用户审到旧图。
